# 题目通俗讲解 — Problem 3 (DNA Enhancer 活性回归)

> 法学背景 5 分钟看懂版。多用"好比"、"通俗说就是"。

---

## §1 这题在干嘛（用最通俗的话）

- **题目 1 句话**：给你一段 DNA 序列（ACGT 字母串），让你预测它在两种情况下作为"基因增强子"的活性强度。
- **类比**：好比拿一段 1000 字的密码（只用 ACGT 四个字母），让你预测它能让"灯泡"亮多少瓦——一种是"发育阶段"的灯，一种是"日常维持"的灯。两种活性分别打分。
- **输入**：DNA 字符串（例如 `"ACGTTGCA...AAGGTT"`，长几百个碱基）。
- **输出**：两个浮点数（developmental 活性分数 + housekeeping 活性分数）。
- **评分**：测试集上算两个 Pearson 相关系数（预测的 vs 真实的），越接近 1 越好。

---

## §2 什么是 enhancer（生物背景，3 分钟版）

- **基因表达** = DNA 被转录成 RNA 再翻译成蛋白质的过程。通俗说就是"基因要干活了"。
- **enhancer（增强子）= 一段 DNA 序列，它本身不编码蛋白，但能"催化"附近基因的表达**。
- 好比一段 DNA 是一首乐谱，enhancer 不是音符本身，而是乐谱旁边写的"这里加大音量"的标记。
- 同一段 enhancer 可能在不同细胞类型 / 不同时间点活性不同：
  - **developmental（发育型）**：胚胎发育时活跃，成年后关闭。好比"小时候才用的玩具"。
  - **housekeeping（管家型）**：所有细胞、所有时间都活跃，维持基本生命活动。好比"每天都要用的牙刷"。
- 这道题就是同时预测一段 DNA 的"发育型"和"管家型"两个活性强度。

---

## §3 什么是 GENErator-v2（模型背景）

- **中关村学院自研的 DNA 大模型**，1.2B 参数（对比：GPT-3 是 175B，所以是个小号的 GPT，但够大）。
- 用 **Transformer 架构**在大规模 DNA 序列上做**自监督预训练**（学 DNA 的"语法"）。
  - 通俗说就是：先让模型读海量的 DNA 序列，让它学会"什么样的 ACGT 组合常一起出现"，类似让人先读完所有古文再做翻译。
- 用 **6-mer tokenizer**：把 DNA 序列每 6 个碱基切成一个 token（"ACTGCC" = 1 个 token）。
  - 好比把英文按词切（"hello" 是一个词），不是按字母切。
  - 举例：DNA 序列长 60bp（碱基对），切成 60/6 = 10 个 token；如果你给的序列长 65bp 不是 6 的倍数，tokenizer 直接报 OOV。考场要做的就是先把序列截到 `(len // 6) * 6`。
- **加载方式**：HuggingFace `AutoModel.from_pretrained(..., trust_remote_code=True)`。
- **关键限制**：序列长度必须是 6 的倍数（不然 tokenizer 报 OOV 错误）。

---

## §4 我们要做什么（任务流程）

通俗说就 4 步：

1. **加载 GENErator-v2** 当作"理解 DNA 的大脑"（**不动它的权重**）。
2. **加一个"评分头"**：在大脑输出后接一个简单的 Linear 层，输出 2 个数字（两种活性分数）。
   - 好比给一个博士配一个助理，博士看完 DNA 给出"理解向量"，助理负责把"理解"翻译成具体分数。
3. **训练评分头**：用提供的 train 集（DNA + 真实分数），让评分头学会从大脑的输出预测分数。
4. **测试**：在 test 集上跑评分头，输出 CSV，跟监考的真实分数算 Pearson。

**为什么冻结 backbone**：
- 1.2B 全参微调一是显存爆，二是数据不够，三是会破坏预训练学到的知识。
- 好比：博士已经读完了所有医学书，你只是教他做一道新题，不需要让他重新学医。

---

## §5 怎么算评分（Pearson）

- **Pearson** = 衡量两组数变化趋势是否一致的指标（不管绝对大小，只看相对关系）。
- 范围 `[-1, 1]`，1 = 完美正相关，0 = 没关系，-1 = 完美反相关。
- 通俗说：如果真实分数高的样本你也预测高，真实分数低的你也预测低，Pearson 就接近 1，**不需要数字绝对相等**。
- 这题输出**两个 Pearson**（一个 dev 维度，一个 hk 维度），监考会取某种组合（可能是平均、min、加权）。
- **DeepSTARR 原论文 baseline Pearson ~0.6**，我们目标：
  - `> 0.4` 算合格
  - `> 0.55` 算优秀
- 为什么 0.4 算合格、0.55 算优秀？DeepSTARR 论文（这道题数据集的原作）用 CNN 跑出 ~0.6。我们用更大的 GENErator-v2 + 冻结 + 小回归头，理论上应该达到甚至超过 0.6。但考场只有几小时，不会调到最优——所以 0.4 是"模型学到东西了"的下限，0.55 是"可以拿大部分分"的及格线。

## §6 这题的难点和加分点（不要陷阱）

### 难点
- **难点 1（最容易踩）**：6-mer 长度约束 → 输入 DNA 必须长度是 6 的倍数，否则 tokenizer 报错。提交前一定要 `len_truncated = (len // 6) * 6`。
- **难点 2**：1.2B 模型显存（A100 80G 也可能爆）→ 必须冻结 backbone + bf16 + 可能 batch_size 调小。
- **难点 3**：双头回归 vs 双模型（设计选择）→ 单模型双头通常更优（共享特征），但加分项是"在 README 解释为什么"。

### 加分点
- **加分点 1**：解释池化方式选择（mean vs CLS vs last） + trade-off。
  - 例如 README 里可以这么写："本方案选择 mean pooling 而非 [CLS]，原因有二：(1) GENErator 是 DNA 任务专用模型，[CLS] 位置在预训练阶段没有明确监督信号，表征质量可能不如全序列平均；(2) DeepSTARR enhancer 活性是序列整体特征的反映，mean pooling 能更好聚合所有 6-mer 的贡献。"
- **加分点 2**：解释 lr / warmup / scheduler 设计逻辑。
- **加分点 3**：在 README 给出 train/val 双 Pearson 曲线（说明监控了过拟合）。

## §7 不要做的事

- ❌ **不要全参微调**（OOM 风险高 + 数据不够）。
- ❌ **不要忘记** `tokenizer.padding_side` / `pad_token` / 6-mer 截断。
- ❌ **不要用 argmax 类操作**（这是回归不是分类）。
- ❌ **不要在 test 集上 shuffle**（顺序必须严格保持）。
- ❌ **不要把两个 Pearson 平均完报一个数**（题目要两个独立的）。
